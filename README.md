# AMML1
# Ранжирование русскоязычных фрагментов

## Итог

Финальное решение: каскад из замороженных предобученных моделей-оценщиков, дообученного BGE-реранкера и LightGBM-ранкеров второго уровня. Метрика соревнования: средний по запросам NDCG@10.

**Воспроизводимая в ноутбуке оценка: 0.969153 OOF NDCG@10** (групповая 5-fold валидация по запросам, 3 042 размеченных запроса, усреднение по 4 наборам seed).


## Соблюдение правил соревнования

- Открытые датасеты для дообучения не использовались. Обучение идёт только на `train.csv` соревнования.
- Дообучение есть на двух этапах: BGE-reranker-v2-m3 дообучается по запросам (по 4 фолдам, верхние 12 слоёв + голова), а LightGBM (LambdaRank, XE-NDCG и регрессия ожидаемого вклада в NDCG) обучается на размеченных строках train.
- Giga-Embeddings, Qwen3-Reranker-4B, Jina-reranker и RuModernBERT-reranker используются как замороженные предобученные оценщики. Их оценки подаются в деревья как признаки.
- Все веса моделей загружаются с Hugging Face по зафиксированным ревизиям, их хеши проверяются в коде.

## Метод

Для каждого вопроса Jina дважды читает все предложенные фрагменты целиком. Во втором проходе порядок фрагментов обратный. Среднее двух оценок входит в деревья вместе с оценками Giga-Embeddings, RuModernBERT и Qwen3-Reranker-4B с двумя инструкциями. Деревья также используют совпадения слов, данные о заголовке и другие лексические признаки.

LambdaRank и XE-NDCG обучаются ранжировать фрагменты, третье дерево предсказывает вклад каждого фрагмента в NDCG запроса. Оценки этих моделей дополняются оценкой BGE.

Для снижения разброса деревья обучаются с исходными параметрами случайности и ещё трижды с фиксированными начальными значениями 805, 1907 и 3031. Итогом служит среднее четырёх прогнозов.

Финальная подгонка деревьев использует все 31 530 размеченных строк. Предсказания BGE для теста усредняются по четырём обучающим разбиениям.

### 2. Стекинг второго уровня

Признаки: оценки моделей (значение, ранг, отклонение от максимума, z-скор, softmax внутри запроса), оценки соседних фрагментов, лексические признаки, признаки дат, сущностей, типа вопроса и ответа в соседних предложениях.

| Модель второго уровня | OOF NDCG@10 |
|---|---:|
| CatBoost (800 деревьев) | 0.96077 |
| HistGradientBoosting | 0.96107 |
| CatBoost (вариант `catq`) | 0.96110 |
| LightGBM lambdarank (бинарная цель) | 0.96215 |
| LightGBM lambdarank | 0.96261 |
| **Смесь LightGBM 0.5 + LightGBM 0.5** | **0.96313** |

Равные веса по всем моделям дали 0.96225, подобранные веса +0.00087 к равным (прирост на всех 5 фолдах). Дообучение BGE на фолдах и стекинг подняли результат с 0.949 до 0.963.

### 3. Что не дало прироста

| Идея | Результат |

В финальный вариант вошли: дообучение BGE по фолдам, независимые zero-shot оценки (Giga, Qwen3-Reranker с двумя инструкциями), LambdaRank и XE-NDCG на втором уровне, усреднение по нескольким seed.

## Среда разработки и запуска

- Разработка и первоначальные эксперименты: Windows, VS Code, Python 3.12.
- Обучение и настройка моделей: VS Code на Windows с GPU NVIDIA RTX 5070 (12 ГБ видеопамяти).
- Проверка воспроизводимости и финальный инференс: Google Colab (Linux, Python 3.13, GPU). Сохранённый запуск в ноутбуке шёл на PyTorch 2.14.1+cu130.
- Итоговый файл `submission.csv` сформирован в Google Colab.
- Ноутбуку нужен Python 3.11 или новее (используется `hashlib.file_digest`).
- Первая ячейка в Colab ставит собственные версии пакетов и использует предустановленный torch, а вне Colab устанавливает пакеты из `requirements.txt` (рассчитан на CUDA 12.8). Поэтому версии в сохранённом Colab-запуске отличаются от `requirements.txt`; для запуска строго с закреплёнными версиями используйте режим VS Code / чистое окружение с `pip install -r requirements.txt`.
- Для полного расчёта без кэшей нужен GPU с BF16 
- В репозитории только три файла: `solution.ipynb`, `requirements.txt`, `README.md`. При запуске ноутбук создаёт служебные файлы (`solution_selfcontained_runtime.ipynb`, `ranking_output/`) в рабочей папке
## Запуск в VS Code (Windows / Linux)

Скопируйте `solution.ipynb` и `requirements.txt` в отдельную рабочую папку, положите рядом `amml-ranking-competition-2026.zip` (или задайте `RANK_DATA`), выберите ядро Python 3.12 и выполните все ячейки. Нужны NVIDIA GPU с BF16 и torch `cu128`; первая ячейка ставит пакеты из `requirements.txt`, если файл находится в текущей рабочей папке.

## Запуск в Google Colab

1. Откройте `solution.ipynb` в Google Colab.
2. В настройках среды выполнения выберите GPU.
3. Загрузите исходный архив соревнования `amml-ranking-competition-2026.zip`, когда ноутбук запросит его.
4. Выполните ячейки ноутбука последовательно через **Runtime → Run all**. Первая ячейка устанавливает необходимые для Colab зависимости; отдельный `pip install -r requirements.txt` в Colab не требуется.
5. При первом запуске без сохранённых измерений ноутбук загружает необходимые модели и вычисляет признаки самостоятельно. Это может занять значительное время и потребовать большого объёма GPU-памяти. Нужен GPU с поддержкой BF16 (L4 или A100).
6. После выполнения ноутбук создаёт `submission.csv` в каталоге `ranking_output`.

Это необязательный режим. Файлы не входят в репозиторий; без них ноутбук считает все признаки сам. Для CPU-повтора нужны все три файла одновременно:
